# 单店美容收银台重构计划

日期：2026-10-16  
需求见：`doc/需求文档.md`  
约束：目前只有一家门店，改造成本要小。

## 1. 结论

不换技术栈，不重写收银。在现有 Electron 客户端上加「会员档案 + 卡账本」，数据用本机 SQLite。商品、扫码支付、小票、员工、登录继续走现在的 fuint 接口。

这样不用另买服务器，也不用等远端后端发版。单店一台主收银电脑足够。第二台收银机或第二家店不在本期。

## 2. 方案

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A. 只改界面，等 fuint 后端加接口 | 客户端先做页面，卡和日志仍请求 `backendApi` | 后端不在本仓库，接口没有皮肤、疗程卡、本金赠金分账。页面做了也落不了账 |
| B. 本机 SQLite（采用） | 主进程建库，渲染进程用 IPC 读写卡、日志、标签 | 一台电脑即可。支付仍用现有接口。换电脑要拷数据库文件 |
| C. 店内再装一套服务 | Node + SQLite 或 MySQL，收银端改连新服务 | 能多台收银，但要维护进程、备份和局域网，超出当前成本 |

采用 B。表结构按需求文档来，以后若要第二台收银，把同一套表迁到店内小服务，客户端只改数据入口。

明确不改：

- Vue 2.7、Element UI、Electron 22、webpack 构建
- `src/renderer/api` 里现有的商品、结算、打印调用
- 卡券核销页。次数型券保持原样，疗程卡走新卡模块，两套不混用

## 3. 目标结构

```
收银台窗口
  今日待办          生日、即将到期、很久没来
  收银（现有）      认会员后带出等级、过敏、卡、储值
  会员              档案、标签、历史、护理日志
  卡                开卡、充值、转卡、退卡、冻结、流水
  设置              四档折扣、充值赠送、积分兑换项、自动标签阈值

Electron 主进程
  SQLite 文件       userData/vip-store.db
  IPC               档案、卡、日志、待办的全部写入

现有 fuint 接口（不动账本规则）
  会员主数据、商品、购物车、支付、订单、打印
```

会员姓名和手机仍以 fuint 会员为准。本地 `member_profile` 只多存皮肤、过敏，用 `memberId` 对应。开单扣储值或划卡时，本地账本先记账成功，再按现有结算接口收剩余的扫码或现金。本地记账失败则整单停住，不出现「钱扣了、次数没扣」。

## 4. 分期

每期都能单独上柜使用。估的是一名熟悉本仓库的人的开发日，不含联调支付渠道。

### 第 1 期（约 8～10 人日）：能认人、能划次卡

- 主进程 SQLite 与 IPC，库文件放 Electron `userData`
- 会员编辑增加皮肤状况、过敏备注
- 会员详情：档案、储值两个数、剩余卡、消费（读现有订单接口）、到店频率
- 计次 / 疗程卡：开卡、核销、剩余次数、变更日志
- 收银认会员后展示过敏和剩余次数，划卡写入日志
- 小票补剩余次数

做完即可替换「用次数券冒充疗程卡」。

### 第 2 期（约 6～8 人日）：储值分账和等级积分

- 储值卡：本金 / 赠金、充值方案、先本金后赠金
- 充值、退卡（只退本金）、冻结
- 四档等级折扣接到结算
- 积分按实付累计，兑换项扣积分出 0 元单
- 积分和储值的变更日志

现有「一个余额数字」的充值弹窗不再作为入账入口，避免两套余额。

### 第 3 期（约 5～7 人日）：其余卡、护理、待办

- 限时卡、体验卡、活动礼包卡、闺蜜共享卡（最多 3 人）
- 转卡
- 护理日志（只追加）
- 手工标签 + 自动标签（高消费、很久没来）
- 今日待办和回访记录（不发短信）

第 3 期之前，生日字段已经在档案里，只是没有待办列表。

## 5. 代码落点

| 位置 | 改动 |
| --- | --- |
| `src/main/services/vipDb.js` | 新建。建表、迁移、全部写入 |
| `src/main/services/ipcMain.js` | 注册 `vip:*` 通道 |
| `src/renderer/api/vip.js` | 新建。渲染进程只通过这里调 IPC |
| `src/renderer/router/constantRouterMap.js` | 增加会员详情、卡管理、待办入口 |
| `src/renderer/views/cashier/components/memberList.vue` | 档案字段、入口改到详情，余额充值改走新储值 |
| `src/renderer/views/cashier/` 结算相关 | 折扣、划卡、储值支付方式 |
| `src/renderer/views/cashier/components/receiptPaper.vue` | 小票增加扣次和本金赠金 |
| `src/renderer/views/member/` | 新建详情、护理日志 |
| `src/renderer/views/card/` | 新建开卡与流水 |
| `src/renderer/views/home/` 或收银首页 | 今日待办 |

`better-sqlite3` 作为主进程依赖，同步写入，避免并发把余额写穿。卡和储值的变动放在一个 SQLite 事务里：改余额、插 `card_ledger` 同时成功或同时失败。

金额在库里用整数分。界面再换成元，保留两位。

## 6. 关键规则（实现时按此，不再另定）

- 储值扣款：先本金，后赠金。退回按原构成退。
- 退计次卡应退金额 = 实收 / 购买次数 × 剩余次数，四舍五入到分。赠送次数不退钱。
- 积分：实付现金、扫码、储值本金每 1 元 1 分。赠金和划卡不计分。
- 等级折扣只影响新单。
- 到店频率：消费单、护理日志、划卡，同一天合并为 1 次。
- 自动标签默认：近 90 天实付 ≥ 3000 为高消费；最近到店早于 60 天前为很久没来。
- 变更日志不提供修改和删除。

## 7. 备份与风险

库文件只有一份。主进程启动时若距上次备份超过 1 天，把 `vip-store.db` 复制到 `userData/backup/`，只留最近 14 份。设置页提供「立即备份」和备份路径说明。换电脑时拷贝该文件即可。

| 风险 | 处理 |
| --- | --- |
| 本地账和 fuint 订单不一致 | 划卡、扣储值在本地事务成功后才提交剩余支付。支付失败则本地事务回滚 |
| 旧的单一余额里已有钱 | 第 2 期上线前导出一份名单，由店长确认后记入本金，赠金记 0。不做自动双写 |
| 原生模块编译 | `better-sqlite3` 需对 Electron 22 重编译。第 1 期第一天先打通 IPC 读写，再做业务 |
| 两台电脑同时收银 | 本期不支持。第二台只查询会把账写乱 |

## 8. 完成标准

与需求文档第 7 节的 8 条场景一致，并加上：

- 断网时仍可查本地卡、日志、储值；扫码支付仍依赖现有接口，断网则不能扫码
- 故意在核销过程中失败一次，次数和日志都不变
- 备份目录里能找到按天复制的数据库文件
